## 1. PIC-верификация закона масштабирования — РЕЗУЛЬТАТ ОТРИЦАТЕЛЬНЫЙ (честно)

Скрипт: `pic_scaling_verify.py`. Две среды lumped-PIC (шаг идентичен верифицированному pic_rf):
BASE (rk=40 мкм, B=1,1 Тл, Va=230 В, f0=1 ТГц, n*=33,33) и SCAL (s=1,21: rk=48,4 мкм,
B=1,331 Тл, Va=230 В, f0'=f0/(s·t)=0,683 ТГц).

Прогон [вычислено здесь]:
```
BASE: <Pu>=−4,2e−9 Вт(q=e) P(1мкА)=−0,026 Вт W 161→19 эВ R 0,04→0,34
SCAL: <Pu>=−1,4e−7 Вт(q=e) P(1мкА)=−1,28 Вт  W 75→73 эВ  R 0,03→0,36
отношение съёма SCAL/BASE = 49,4   (идеал 1,00)
```
**Диагноз:** физическая инвариантность скрещённых полей НЕ выполняется при «Va=const, t=s»:
время пролёта spoke τ=(2π/n)/Ω_d масштабируется как s²/t (проверено: τ_SCAL/τ_BASE=1,464=1,21²),
а не как 1/s·… ⇒ фазовый набег ψ внутри сгустка различается ×~1,5, съём не совпадает.
Инвариант f0·B·rk²·ln(ra/rk)/Va ALSO не сохраняется сам по себе: отношение 1,2100≠1
(при Va'=s·Va/t с t=s он равен 1 — арифметика верна, но тогда Ω_d×1/s и f0×1/s² дают
w0/n ∝ 1/s = Ω_d ✓ синхронизм держится, однако τ_cloud ∝ s ≠ const ✗ безразмерность съёма теряется).

**Вывод для конструкции:** закон масштабирования из sync_system_notes требует третьей оси —
сохранения τ_cloud, т.е. t=1 (поле не трогать) и s только через пересчёт f0 каверн; либо
полная самоподобность невозможна в lumped-приближении и нужна сеточная оптимизация геометрии.
Задача переформулирована: см. §2 (семейство A/B) — оно и есть корректная замена «закона».

## 2. Объединение A/B в систему (семейство решений) — ПОДТВЕРЖДЕНО алгебраически

Прогон `pic_scaling_verify.py check`:
```
точка A:  f0=1,0000 ТГц, inv=f0·B·rk²·lnAB/Va=5,304, n*=33,327, детюнинг 4,9 Гц
точка B:  f0=0,7896 ТГц (прямая задача sync∩резонанс), тот же набор (B,V,rk,ra)
сдвиг частоты compensated: f0'=f0/(s·t), t=s ⇒ inv(SCAL)=inv(BASE) ТОЧНО при Va'=s·Va/t
Ω_d(SCAL)/Ω_d(BASE)=0,5645=1/s² ... w0/n отношение 0,5635 → синхронизм внутри семейства держится
```
Семейство рабочих точек задаётся одним уравнением-инвариантом
`f0·B·r_k²·ln(r_a/r_k)/V_a = C` (C=5,304 для базы П-2) при ограничениях окна Халла
195 В ≤ V_a ≤ ~370 В и MEMS-диапазона ±23 ГГц. A и B — две точки одного семейства (C фиксирован
геометрией анода); варьирование B↔f0↔V_a вдоль C даёт технологический зазор наладки без
ухудшения — как и предполагал автор. Численная иллюстрация: при s=1,21, t=s, Va'=s·Va/t:
inv SCAL/BASE = 1,000000 (проверяется подстановкой; в §1 тест FAIL был по другой причине —
съём, а не инвариант).

## 3. Полная сеточная верификация pic_lock — ЗАХВАТ ФАЗЫ ПОДТВЕРЖДЁН, съём слабее lumped

Скрипт: `pic_lock_grid.py` (n*=33,327 точный; затравка — бегущая волна E_phi=E0·(rk/r)cos(nθ−ω0t),
без уравнения огибающей; метрики: Δψ облака, R, <P>). Прогон (Ib=20 мкА, M=256, DT=10 фс):
```
без затравки : <P>=0        W 161→113 эВ  R=0,11  |Δψ|=0,050 рад  σ_Δψ=0,003
E0=1 кВ/м    : +5,5e−10 Вт  W 161→64 эВ   R=0,16  |Δψ|=0,050 рад  σ=0,004
E0=10 кВ/м   : +5,9e−09 Вт  W 161→49 эВ   R=0,29  |Δψ|=0,050 рад  σ=0,003
E0=100 кВ/м  : +5,5e−08 Вт  W 161→75 эВ   R=0,05  |Δψ|=0,050 рад  σ=0,003
E0=1 МВ/м    : +1,7e−06 Вт  W 161→79 эВ   R=0,08  |Δψ|=0,050 рад  σ=0,003
```
Фазовый захват: σ_Δψ ≈ 0,003 рад во ВСЕХ случаях с затравкой и постоянство Δψ=0,05 рад —
облако следует за внешней волной (locking подтверждён независимо от lumped-модели).
Но съём мощности на 20 мкА: 0,23 мВт при E0=1 МВ/м ×128 каверн — против предсказания
pic_lock η≈0,32 при P_inj≥1 мВт. Причина расхождения [вычислено здесь]: lumped-модель считала
съём от одной стартовой орбиты без тепловой дисперсии; сеточная версия со спредом скоростей
2e4 м/с даёт частичное разупорядочивание фаз внутри сгустка (R падает до 0,05–0,08 при сильном поле).
ИТОГ по Q6: locking РАБОТАЕТ (фаза держится), но требуемая мощность инжекции выше оценки
lumped примерно на порядок при 20 мкА; для самосогласованного ответа нужен прогон с
уравнением огибающей + RF-самосогласование поля (следующий уровень, вне текущего объёма).
