# phicore — эталонное ядро Ф-чисел

Библиотека точной арифметики линеек (линия `notes/чтение 2026-08-31/
00-ЛИНИЯ`, §3 — все одиннадцать шагов построены). Ни одного float в
вычислениях; рабочий скаляр — контейнер v6 (слово автора 01.09:
чужой дробный тип — тупик), носитель класса 1 — собственная пара
целых `rational.Q`. Чужой универсальный тип выселен ТОТАЛЬНО
(total_nonFraction, слово автора 02.09): в ядре ни одного ввоза —
замер 17.09 `[вычислено здесь]`: `from fractions` в `phicore/*.py` 0
(восемь упоминаний в докстринге объясняют выселение и в счёт не идут);
в приёмках ядра ввоза три из 53 наборов, и это названо, а не спрятано:
`proto/test_phicore_affine_div.py:19` и `proto/test_phicore_profile.py:16`
держат им СВЕРКУ независимым типом, `proto/test_phicore_ieee.py:11` —
мёртвый ввоз, затенённый `phicore.rational.Q` четырьмя строками ниже.
Этапы выселения — в
`notes/миграция на контейнер v6 — план выселения Fraction, 2026-09-01.md`.
Первые принципы: AIAΣA (отказ вместо ложного класса), Ф-число в явной
полной записи, ОП-геометрия (дискретность изначальна — сертификаты
сетки вместо приближений).

## Три правила, вкрученные в устройство

1. **Отказ вместо ложного класса** — пустая ячейка ФIOS и несведённый
   носитель дают `Unresolved` с явными Ф-записями обоих операндов.
2. **Явная запись** — всякий `record()` печатает `Φ(C=…, параметры)`;
   десятичная сторона — только сертификатом сетки по явному запросу.
3. **Ноль — состояние; знак и провенанс не теряются** — род нуля
   переживает операции; `−√3 ≠ √3`; `(ω−ω)+5` поглощает, `(ε−ε)+5` уступает.

## Пользование

```python
from phicore import (Q, combine, zeta, GammaValue, PI, PiMonomial,
                     iteration_limit, IntPoly, AlgebraicNumber)

zeta(2)                              # Φ(C=10 …, q=1/6, e=2) — π²/6 точно
zeta(Q(-1))                          # Q(-1, 12) — из Бернулли
combine(GammaValue.of(Q(1, 3)),
        GammaValue.of(Q(2, 3)), "*")     # 2π/√3 точно (отражение)
iteration_limit(IntPoly([2, 0, 1]), IntPoly([0, 2]), Q(2))
                                     # AlgebraicNumber √2 — класс 19 → 3
Q(2) ** Q(1, 2)                      # √2 ТОЧНО — переход класса 1 → 3
combine(PI, AlgebraicNumber.from_root(2, 2), "+")  # с 03.09 — Mixed (структурная запись суммы разных баз), прежде — Unresolved
```

  перемножения доходит 0,65 % подмножеств, время 4,88 → 0,139 с, выигрыш
  35× (`proto/bench_zassenhaus.py`, 16 проверок). Цена перебора замерена:
  3,55 мкс на подмножество, отсюда r = 24 — около 35 с, r = 32 — около
  2,4 часа; порог r ≤ 24 держится явным отказом. **Вторая дорога с
  04.09 есть**: `lattice.py` (точный LLL: μ и ‖b*‖² дробями, правка по
  месту) и `lllfactor.py` (LLL 1982 — множитель приходит коротким
  вектором решётки, перебора нет вовсе; ненахождение при взятой точности
  есть доказательство неприводимости, а не незнание). Дороги сверены: 35
  многочленов и лестница Суиннертон-Дайера — расхождений 0. Замер
  (`proto/bench_lllfactor.py`, приёмка 25/0): на степени 8 — 0,004 с у
  перебора против 0,106 с у решётки, на степени 16 — 0,013 с против 69,7 с.
  Решётка над коэффициентами полиномиальна, но постоянная велика.
  **Третья дорога с 04.09 есть**: `vanhoeij.py` — решётка не над
  коэффициентами (размерности n), а над ПОДМНОЖЕСТВАМИ множителей
  (размерности r + s): степенные суммы корней подмножества целы и малы,
  и решётка следов вытаскивает их без перебора. `intfactor` за порогом
  r > 24 теперь идёт этой дорогой, а отказ остаётся лишь на случай, когда
  разбиение не собралось; всякий найденный набор проверяется делением,
  потому тихого ответа быть не может. Согласие с перебором: 41 совпало,
  13 переходов на перебор, 0 расхождений; лестница — 0,015 / 0,30 / 9,92 с
  на степенях 8 / 16 / 32 (`proto/bench_vanhoeij.py`, приёмка 30/0).
  Приведение решётки с 04.09 целочисленное (`lattice.lll`, Cohen 2.6.7):
  дробей нет вовсе, вместо μ — целые λ и определители Грама, и это дало
  5–10× на обеих дорогах (следы 54,7 → 9,92 с на степени 32; LLL 1982
  564,8 → 69,7 с на степени 16); дробный путь остался эталоном
  (`lattice.lll_rational`) и сверяется приёмкой. **Порог снят числом**:
  Суиннертон-Дайер степени 64 (r = 32 > 24) разложен решёткой следов за
  1 426,8 с и признан неприводимым; перебор на той же ступени стоил бы
  около 8 680 с — это вычисление из замеренной постоянной (§441), а не
  замер.
* Точное умножение на ядре BLAS (`exact_gemm.py`, Одзаки) — есть при любой
  ширине с классом 22 на значении; порог ядра на CPU 2,5× (метка) / 7,5×
  (ветвь) от float32 — ниже только на целочисленных тензорных ядрах, их
  в среде нет.
* Аффинные засечки (`affine.py`): x − x = 0, зонотопы для сетей — есть;
  с 04.09 есть и обратный элемент, деление и корень — оба канонических
  приближения (Чебышёв-минимакс и min-range, Stolfi–de Figueiredo 1997)
  на точной рациональной арифметике, округление к сетке наружу, засечка
  через ноль (и левее нуля для корня) — отказ поимённо; замер: x/x уже
  интервального втрое-семеро на семействе из девяти форм, накрывает
  единицу на каждой; у корня δ Чебышёва втрое-вчетверо меньше, min-range
  ложится на образ отрезка
  (`proto/test_phicore_affine_div.py`, 41 проверка). Ширина зонотопов
  замерена до D = 2048 (`proto/bench_zono_width.py`): пик коэффициентов —
  тождество n·D²·8 байт, символов D + 3, включение 0 нарушений; D = 4096
  в среду не помещается — отказ, не оценка. Приближений выше первой
  степени нет.
