# Правила chatman для проекта THz

Этот проект следует профильно-общим правилам, установленным в репозитории `czts-spec/dtba3a-del`, а также использует `chatman` как локальный канон работы с чат-логами и контекстом.

## 1. Авторство и принадлежность

- Автор проекта — владелец профиля (`dtba3a`), а не инструмент.
- Инструмент не имеет и не претендует на авторство.
- В коммитах не ставится трейлер `Co-Authored-By`.
- В поле `author` / `committer` инструмента не записывается до первого коммита в сессии.
- Перед первым коммитом в сессии выполняется:

```bash
git config user.name  "dtba3a"
git config user.email "dtba3a@gmail.com"
```

- Вместо графы «моё» применяется ось происхождения:
  - `[в корпусе]`
  - `[внешний источник]`
  - `[вычислено здесь]`

## 2. Запреты и обязательства

### Запрещено

- Трейлер `Co-Authored-By` в сообщениях коммитов.
- Запись инструмента в поля `author` / `committer`.
- Пометки «моё», «моя находка», «своим остаётся» и аналогичные формулировки в любых файлах.
- Подписи и футеры инструмента в текстах, PR и комментариях.

### Обязательно

- Перед объявлением нового знания — поиск по материалам профиля.
- Описание кейса и команды исправления истории должны быть зафиксированы в проекте в понятном и проверяемом виде.
- Любое утверждение, которое претендует на новизну, должно быть проверено по корпусу и по уже существующим материалам профиля.

## 3. Правило ветки и проекта

- В проекте используется только одна ветка: `main`.
- Проектные особенности хранятся в `.chatman/`, а не в отдельной ветке.
- Решения и данные проекта живут в репозитории как локальные данные, а не в ветках-ответвлениях инструмента.

## 4. chatman / chatlog

`chatman` — канон работы с рабочими чатами, стенограммами и контекстом.

Нормальный рабочий цикл проекта:

```bash
chatman repos
chatman find --prompts --grep '...'
chatman find --context 77 --around 3
chatman search '...' --fuzzy 1
chatman rules
chatman export
```

### Правила использования

- Стенограммы не переписываются и не «причёсываются»; они должны сохраняться как дословная запись.
- В проекте используются только те логи, которые относятся к `cwd` этого репозитория.
- Экспорт логов должен быть сознательным и контролируемым действием.
- Контекст чата и решения, принятые в нём, не должны исчезать в памяти без фиксации в репозитории.

## 5. Канон этого проекта

Проектный канон расположен в `.chatman/rules.md` и дополняет общий профильный канон.

Порядок действий в проекте:

1. Проверить, нет ли уже решения в корпусе профиля.
2. Использовать `chatman` для поиска, поиска по стенограммам и логов.
3. Сохранять контекст и результаты в репозитории.
4. Не создавать дополнительные ветки ради локальной особенности проекта.
5. Коммиты допускаются только после проверки и согласования с правилами профиля.

Это правило действует для всех работ в `czts-spec/THz`.
